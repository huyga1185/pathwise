### Luồng auth hiện có (sau T10)

1. `POST /api/v1/auth/register {email, password, storeName, fullName?}` → 201, tạo store và OWNER `PENDING_VERIFICATION` trong một transaction, sau commit gửi OTP `VERIFY_EMAIL` (email lỗi vẫn 201). `POST /api/v1/auth/email/verify {email, otp}` → ACTIVE; `POST /api/v1/auth/email/verify/resend {email}` → luôn 204 (T13).
2. `POST /api/v1/auth/log-in` → `{accessToken, accessTokenExpiresAt, refreshTokenExpiresAt, user}`; chưa verify → 403 `EMAIL_NOT_VERIFIED`, DISABLED → 403 `ACCOUNT_DISABLED` (chỉ khi đúng mật khẩu); refresh token qua cookie `refreshToken` (`Path=/api/v1/auth; SameSite=Strict; HttpOnly; Secure`) cho web, hoặc trong body khi có header `X-Client-Platform: mobile`.
3. `POST /api/v1/auth/refresh` (cookie hoặc body `{refreshToken}` cho mobile) → xoay vòng, grace 3 s cho request đồng thời, reuse → revoke family, token hết hạn → `EXPIRED` + 401, user không ACTIVE → 401 (T13).
4. `POST /api/v1/auth/log-out` (public; cookie hoặc body cho mobile) → revoke family, luôn 204, web xoá cookie.
5. Session = refresh token family (P-07), access token mang claim `sid`: `GET /api/v1/auth/sessions` (mỗi family còn token ACTIVE chưa hết hạn một dòng, kèm `current`), `DELETE /api/v1/auth/sessions/{sessionId}`, `POST /api/v1/auth/sessions/revoke-others`.
6. Đổi mật khẩu 3 bước: `GET /api/v1/auth/update-password` (gửi OTP) → `POST /api/v1/auth/update-password/verify {otp}` (set cookie token+ticket, token gắn userId) → `POST /api/v1/auth/update-password {password}` (cookie; từ chối token của user khác).

## 3. Điểm làm tốt (giữ lại)

- Chia module theo nghiệp vụ (`auth`, `user`, `routeoptimizer`) với `controller/service/repository/dto/model/infrastructure` — dễ hiểu.
- `auth` phụ thuộc `user` qua interface hẹp `UserAccountService` + `UserIdentity`; `user` không phụ thuộc `auth`.
- Refresh token: lưu hash, xoay vòng theo family, phát hiện reuse, pessimistic lock khi rotate — thiết kế đúng hướng.
- OTP: lưu hash, verify atomic bằng Lua, giới hạn số lần thử, cooldown; fail-closed khi Redis lỗi.
- Abstraction provider (`GeocodingProvider`, `MatrixProvider`, `SolverProvider`) — đúng nhu cầu thực tế (D-10 đổi sang Google).
- Validation số điện thoại VN qua libphonenumber, lưu E.164.
- Phân trang có whitelist sort field.
